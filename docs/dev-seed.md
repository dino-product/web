# dev 목데이터 (`npm run seed:dev`)

실운영 전에 초기화할 공용 dev DB(`orbit_dev`, `dev-api.orbi-t.com`)에 화면 확인용 목데이터를 **더하는** 시드다. 기존 행은 지우지 않고, 시드가 만든 계정·발주사 식별자만 기록해 그 범위에서만 SQL을 쓴다. 스크립트는 `scripts/seed-dev.mjs`.

> 아래 식별자·회사 코드는 **2026-11-08 dev 시드** 기준이다. 되돌린 뒤 다시 시드하면 바뀌므로, 그때는 `.seed-dev.dev.json`(`accounts`·`organizations`·`companyCodes`)을 본다.

## 계정 전환

준비: Orbit 계정 SSO 프로필(`orbit-dev`, 권한 세트 `OrbitDevDeveloper` 이상)로 로그인되어 있어야 한다(`aws sso login --profile orbit-dev`).

1. 토큰 만들기(24시간 유효). `web/`에서:

   ```bash
   AUTH_JWT_SECRET=$(aws ssm get-parameter --profile orbit-dev --region ap-northeast-2 \
     --with-decryption --name /orbit/dev/AUTH_JWT_SECRET --query Parameter.Value --output text) \
     node scripts/dev-token.mjs 7
   ```

2. `https://dev.orbi-t.com`을 열고 개발자 도구 콘솔에서 넣는다. `companyId`는 처음 열 발주사 ID다(위 발주사 표).

   ```js
   localStorage.setItem('orbit:accessToken', '<토큰>');
   localStorage.setItem('orbit:accountId', '7');
   localStorage.setItem('orbit:companyId', '5');
   location.href = '/timetable';
   ```

3. 다른 계정으로 바꾸려면 1~2를 그 계정 ID로 다시 한다. 여러 발주사에 속한 계정(7·9·13·15)은 사이드바 아래 발주사 전환으로 옮겨 다닌다.

로컬 `npm run dev`로 볼 때도 같다. 다만 `VITE_API_PROXY_TARGET=https://dev-api.orbi-t.com`으로 띄우고 `http://localhost:5173`에서 넣는다.

### 본인 카카오 계정으로 시드 회사에 들어가기

본인 카카오로 `dev.orbi-t.com`에 로그인한 뒤 회사 코드(예: `WSWFXS`)로 참여를 요청한다. 승인할 총관리자가 시드 계정이므로, 위 방법으로 그 회사 총관리자 계정에 들어가 **조직 설정 → 승인대기**에서 승인한다.

- dev는 푸시가 켜져 있다(`FCM_ENABLED=true`). 앱 기기를 등록한 실계정이면 그 뒤 생기는 작업 이벤트가 푸시로 갈 수 있다.
- 시드를 되돌리면 그 소속도 함께 지워진다. 계정 자체는 남는다.

## 실행

| 단계 | 명령 |
| --- | --- |
| 로컬 리허설 | server에서 `docker compose --env-file .env up -d postgres redis localstack`와 `bootRun`을 띄운 뒤 `npm run seed:dev -- --target=local` |
| RDS 터널(dev, 별도 터미널) | `aws ssm start-session --profile orbit-dev --region ap-northeast-2 --target <dev 노드 ID> --document-name Orbit-DevRdsPortForward --parameters localPortNumber=15432` |
| dev 적용 | `AWS_PROFILE=orbit-dev npm run seed:dev -- --target=dev --confirm-dev` |
| 대조표 다시 보기 | `AWS_PROFILE=orbit-dev npm run seed:dev -- --target=dev --confirm-dev --report` |
| 되돌리기 | `AWS_PROFILE=orbit-dev npm run seed:dev -- --target=dev --confirm-dev --rollback` |

dev 노드 ID는 다음 명령으로 찾는다.

```bash
aws ec2 describe-instances --profile orbit-dev --region ap-northeast-2 \
  --filters Name=tag:Env,Values=dev Name=tag:Role,Values=k3s Name=instance-state-name,Values=running \
  --query 'Reservations[].Instances[].InstanceId' --output text
```

- **필요한 것:** 사진 폴더 `.seed-assets/{site,before,after}/{install,inspect,repair,clean}-NN.jpg`(48장, git 제외). 없으면 시드가 멈춘다.
- **소요 시간:** 로컬 약 5분, dev 약 7분. 완료보고 요청 사례는 예정 종료가 지날 때까지 기다린다.
- **확인 시점:** 진행 보드 캐시가 60초라 직후 화면은 1분 뒤 본다.
- **결과 파일:** `.seed-dev.<target>.json`(시드 식별자 기록)과 `.seed-dev.<target>.report.json`(대조표). 둘 다 git 제외다.
  - **되돌리기는 이 기록 파일로만 한다.** 시드한 PC 밖에서 되돌리려면 이 파일을 팀 드라이브 등에 백업해 둔다.
  - 기록이 있으면 다시 시드하지 않는다. 먼저 `--rollback` 한다.
- **되돌리기 범위:** 기록한 계정·발주사 범위의 행만 지운다. S3에 올린 사진 객체는 앱 권한에 삭제가 없어 남는다.

### 동작 방식

- **서버 API로 만드는 것:** 가입, 발주사, 참여 요청·승인, 유형, 작업의 배정·수락·거절·시작·완료보고·취소, 사진 업로드(업로드 주소 발급 → S3 PUT → 작업 저장), 알림 읽음, 알림 설정, 푸시 기기. 알림과 발신 기록은 서버 이벤트로 자연히 생긴다.
- **SQL(`orbit_dev_rw`, 시드 범위 한정)로 하는 것:** API로 만들 수 없는 일만 한다.
  - 계정·OAuth 연결 넣기, 기기 세션 넣기
  - 작업 유형 지정
  - 시각 사상
  - 발송 성공 6건 만들기
  - 탈퇴 뒤 생긴 연결 해제 재시도 행 지우기
- **시각 사상:** API는 "지금"으로만 동작한다. 그래서 지난 작업은 지금 근처 일정으로 끝까지 진행한 뒤, 그 작업의 사건 시각(등록·배정·수락·시작·요청·완료·알림)을 목표 날짜로 순서를 지키며 옮기고, 일정은 같은 간격만큼 옮긴다.
- **하지 않는 것:** TRUNCATE·FLUSHDB를 쓰지 않고, 실계정·실발주사 행은 건드리지 않는다. 대조표의 `guard`가 시드 계정이 시드 밖 발주사에 소속·알림을 갖지 않았는지 확인한다.
