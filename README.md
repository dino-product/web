# Orbit 웹 UI 프로토타입(front)

Figma `Design.v0`(파일 키 `5K4KURRdWETTXsnlurK6jK`) `웹UI` 페이지의 사무실(발주사) 웹 화면을 React로 옮긴 앱입니다. `../server/`의 실제 백엔드와 연결합니다. 화면 범위·결정의 기준은 [UI 구현 계획](docs/ui-plan.md), 데이터 사용법은 [데이터 계층](docs/data-layer.md), 공통 컴포넌트는 [디자인 시스템](docs/design-system.md)에 있습니다.

## 실행

Node.js/npm, **JDK 21**, 로컬 PostgreSQL·Redis가 필요합니다. DB·Redis는 `server/`의 Docker Compose로 실행할 수 있습니다. [서버 실행 안내](../server/README.md#빠른-시작)를 먼저 확인합니다.

```bash
# 저장소 루트에서, 서버용 터미널
cd server
cp .env.example .env  # 최초 1회. 기존 .env는 덮어쓰지 않습니다
docker compose --env-file .env up -d postgres redis
set -a && source .env && set +a
./gradlew bootRun
```

```bash
# 별도 터미널, 저장소 루트에서
cd dino-web-tmp
npm install
npm run seed:local # 실행 중인 로컬 서버에 개발 데이터 생성
npm run dev        # http://localhost:5173
```

**주의:** 서버 local 프로필은 `create-drop`이며, `seed:local`은 로컬 Postgres public 테이블 전체와 Redis DB를 초기화합니다. 보존할 데이터가 없는 로컬 환경에서만 실행합니다. 시드는 `.env.development.local`과 `.dev-seed.json`을 생성합니다. 시드 후 Vite를 시작하거나 재시작합니다. DB 기본 포트는 54321, Redis는 6379이며 별도 DB는 시드의 `DATABASE_*`/`PG*` 환경 변수를 맞춥니다.

- Vite는 `/api`를 `http://localhost:8080`으로 프록시합니다. 대상 변경은 `VITE_API_PROXY_TARGET`으로 지정합니다.
- `npm run typecheck`: 타입 검사, `npm run build`: 타입 검사·프로덕션 빌드, `npm run preview`: 빌드 미리보기입니다. 임시 로그인은 개발 서버에서만 됩니다.
- Vite 7 + React 19 + TypeScript 5.9 + React Router 7 + Zustand 5, CSS Modules를 사용합니다.
- 화면은 1920px 캔버스를 창 너비에 맞춰 확대·축소합니다. **1920×1080 창**에서 Figma 프레임과 1:1로 같습니다.
- 서버에 저장된 변경은 새로고침해도 유지됩니다. 토큰·계정 ID·선택 발주사는 localStorage에 저장합니다. API가 없는 일부 동작만 로컬 메모리 상태입니다.
- 시드 날짜는 실행 시점의 실제 오늘(Asia/Seoul) 기준입니다. 다음 날에도 오늘 데이터를 보려면 로컬 초기화 영향을 확인한 뒤 다시 시드합니다.

## 개발 로그인 페르소나

'카카오 로그인' 버튼은 현재 **임시 개발 로그인**입니다. 실제 카카오 SDK는 호출하지 않습니다. 이미 로그인했다면 로그아웃한 다음 아래 URL을 새로 열어 로그인합니다.

| URL | 다음 로그인 계정 |
| --- | --- |
| `/login?reset=1` 또는 기본 선택 | 오르빗: OO건설 총관리자, 협력 발주사 직원 |
| `/login?role=staff` | 김운영: OO건설 직원 |
| `/login?user=new` | 아직 가입을 완료하지 않은 개발 계정 → 약관·프로필·온보딩 |

선택은 sessionStorage `orbit:devLogin`에 남습니다. `?reset=1`은 로그인 선택만 기본으로 되돌리며 서버 데이터는 초기화하지 않습니다. 온보딩 계정 5개를 모두 썼다면 다시 시드합니다.

빈 화면은 새 발주사·협력 발주사·데이터 없는 날짜나 필터로 확인합니다. 연결 실패는 실제 API가 닿지 않을 때 표시하고 '다시 시도'로 재조회합니다. 발주사 2곳은 기본 시드에 이미 포함됩니다. 현재 시각은 실제 시각이며 시연 시계는 없습니다.

화면 상태 쿼리는 유지합니다: `/timetable?mode=edit&task=<숫자 ID>`, `/org/members?modal=code|approvals`, `/org/types?tab=employee|technician|work`, `/notifications?filter=unread`.

### '변경된 정보입니다' 모달 재현

1. 오르빗으로 로그인한 두 탭 A·B에서 `/timetable?mode=edit`를 열고 같은 등록 또는 배정 가능한 작업을 읽습니다.
2. A에서 그 작업의 배정 확인 모달을 열어 둡니다.
3. B에서 같은 작업을 다른 기사·시각으로 먼저 배정 확정합니다.
4. A는 새로고침하지 않고 이전 배정을 확정합니다. 필요하면 일정 충돌도 확인합니다.
5. 서버가 이전 `expectedVersion`을 `SCHEDULE-016`으로 거부하면 '변경된 정보입니다'가 열립니다. 확인 후 최신 상태를 다시 읽습니다.

특정 카드·첫 시도 여부와 무관합니다. A가 먼저 최신 데이터를 다시 읽었다면 버전 충돌이 나지 않으므로 두 탭의 읽기·저장 순서를 지킵니다.

## 백엔드 연동

화면별 API·제한은 [백엔드 연동 가이드](../api-integration-guide.html)를 참고합니다. 서버 코드는 계약이며 프론트 연동을 위해 바꾸지 않습니다.

`src/api/devAuth.ts`는 **TEMP-DEV-AUTH**입니다. 시드가 만든 로컬 계정·서버 JWT 키로 브라우저에서 HS256 토큰을 서명합니다. 키가 개발 번들에 들어가므로 운영 키를 넣거나 외부에 배포하면 안 됩니다. 실제 로그인은 `POST /auth/kakao/nonces` → 카카오 SDK(nonce·id_token) → `POST /auth/kakao/login`으로 연결해야 합니다(모두 `/api/v1` 아래). 연결 후 `devAuth.ts`, 스토어 `loginWithKakao`의 `devLogin` 호출, `.env.development.local`의 `VITE_DEV_*` 값을 제거하고 시드의 해당 설정 생성도 제거합니다.

## Figma와 다른 점과 이유

공통
- **작업 상태 표기**: 디자이너 전달사항(2026.10.08)에 따라 옛 표기를 새 표기로 바꿨습니다 — 대기중→등록, 수락대기·배정 대기·대기→배정됨, 수락됨→작업전, 확정→실제 상태, 작업완료→완료, 취소됨→취소(작업 취소 모달·알림 상세 문장 포함), 거절(상태 칸)→등록 + 거절 배지. 진행 보드 탭은 전체·배정됨·작업전·작업중·완료입니다.
- **오탈자 수정**: '충동 확인 후 배치'→'충돌 확인 후 배치', 표 머리글 '직업유형'·'직원유형'(작업 목록·기사 작업이력)→'작업유형', '직총관리자 지정·해제'→'총관리자 지정·해제', 변경된 정보 설명의 겹친 공백, 지연 칩 앞 공백.
- **데이터**: 시안의 예시 이름·날짜(요일 오류 포함)·건수 대신 시드 데이터와 실제 오늘 날짜를 씁니다. 기본 로그인 사용자는 '오르빗'이며 직원 페르소나는 '김운영'입니다.
- **모달 배경**: 시안은 빈 회색이나 이전 디자인 화면 위에 모달을 그렸지만, 실제 흐름대로 지금 화면 위에 어두운 배경을 깝니다(약관 동의, 작업 상세·취소, 계정 탈퇴 확인 등).
- **목적지 시안이 없는 일부 버튼**은 새 화면 없이 동작하지 않습니다: 연결 끊김 안내, 이용약관·개인정보처리방침·안내 보기 링크, 약관 항목 화살표, 관리자 설정 탭, 인쇄, 사이드바 검색(입력만). 주소 검색은 샘플 주소를 채우는 목업 동작만 합니다. **작업내역 출력은 현재 필터를 담아 서버 `/works/export`에서 xlsx를 내려받습니다.**
- **시안에 없는 상태**는 같은 화면의 기존 모양으로 처리했습니다: 비활성 버튼(DS 50% 모양), 열린 필터 목록(DS 드롭다운), 선택지가 없는 필터는 열리지 않음, 완료 블록 색, 대기함 카드 선택 모양 등.

섹션별 주요 결정
- 온보딩: 약관 동의 모달은 모두 미선택에서 시작합니다(선택 동의를 미리 체크하지 않음, 시안은 전체 동의 상태). 프로필 프레임 밖에 따로 놓인 사진 업로드 요소(`1453:12460`)는 쓰지 않았습니다. 로그인 배경 셰이더는 같은 수식으로 렌더한 이미지입니다.
- 타임테이블: 시간 축은 00:00–23:00 1시간 간격(시안 라벨이 불규칙), 블록 위치·너비는 실제 시작 시각·소요 시간으로 계산합니다. 새 작업 등록 시안의 임시 문구('음..', '설')는 실제 값으로 그립니다. 편집 모드 스크롤 막대는 실제 스크롤 비율을 따릅니다.
- 작업 목록: 대기함은 한 쪽 4줄(시안 4줄, 1080px에 표 5줄까지 들어가는 배치), 페이지네이션은 한 쪽을 넘을 때만 보입니다. 상태·기간 필터 선택지(상태 다중, 기간 오늘·이번 주·이번 달)는 열린 모양 시안이 없어 정한 값입니다. 상태 변경 이력이 3줄을 넘으면 상자 안에서 스크롤합니다.
- 진행 보드: 상세 모달은 작업 목록 시안(`785:5490`)과 배치가 다른 보드 시안(`1892:12847`)대로 그립니다('작업 취소'가 오른쪽 열 아래). 탭 건수는 전체 0건일 때만 숨깁니다.
- 조직 설정: 발주사 정보는 서버에 저장된 발주사 명·업종으로 시작합니다. 인력관리 기본 필터는 '직원'입니다. 총관리자 지정·해제 버튼은 이전 시안 근거로 안내 줄 오른쪽에 둡니다. 역할 변경은 서버 API가 없어 로컬 동작이며 회사 코드는 서버 발급값을 표시합니다.
- 유형 설정: 새 유형 행은 목록 끝에 생깁니다(시안은 편집 행 바로 아래). 더보기 메뉴는 한 번에 하나만 열립니다(시안은 두 개가 열린 예시). 활성화·비활성화 확인 모달 3종의 연결은 판단으로 정했습니다(아래 확인 필요).
- 알림: 작업 취소 알림은 상세 페이지(`1807:6719`)로 엽니다. 취소 안내 패널(`1894:8798`)은 디자이너 전달사항('노션에서 제외됨')에 따라 구현하지 않았습니다. 시안이 없는 알림 유형(일정 변경·작업 거절·완료 보고)의 상세 제목·일시 이름은 같은 형식으로 만들었습니다.

## 구현 메모

- **글자 렌더링 보정**: Chrome은 Pretendard 지표를 정수로 반올림해 12·16·24·32·36·48px 글자를 Figma보다 1px 위에 그립니다. 화면 글자는 세로 지표만 바꾼 `'Orbit Pretendard'`(`src/styles/fonts.css`)로, 입력 상자는 원래 지표로 그려 Figma 기준선과 맞춥니다. 자간 -2.5%는 `global.css`가 모든 요소에 글자 크기 비율로 다시 지정합니다.
- 공통 컴포넌트는 `src/design-system`에 있고, 화면에서 모양이 다른 경우만 섹션 폴더에 지역 컴포넌트로 둡니다(예: 새 작업 등록·작업 취소·발주사 업종·기사유형 변경 선택 상자는 Figma 옵션 패널 모양이 서로 달라 각자 구현).
- 모달·드롭다운은 캔버스 안 `#overlay-root`로 포털합니다. 모든 크기는 1920 캔버스 px입니다.
- 글꼴: 화면 글자는 `pretendard` 패키지(SIL OFL 1.1)입니다. 로그인 '카카오 로그인' 글자만 Figma 글꼴 IBM Plex Sans KR SemiBold에서 그 6글자만 뽑은 부분 글꼴(Google Fonts 제공, SIL OFL 1.1, `src/pages/onboarding/assets/fonts/`)을 씁니다.

## 알려진 제한

- 실제 카카오 로그인은 미연결이며 임시 devAuth는 개발 서버에서만 동작합니다.
- 서버 local의 `DenyingWorkTypeAdapter` 때문에 작업 등록에 작업유형을 지정하면 `SCHEDULE-014`로 실패합니다. 유형 없이 등록할 수 있으며 시드 작업의 유형은 SQL로 연결합니다.
- 일정 응답의 기사·등록자·작업유형 이름은 null이라 프론트가 인력·유형 ID로 조합합니다. STAFF는 참여 인원 API가 OWNER 전용이고 로컬 기사 어댑터도 비어 있어 기사를 볼 수 없습니다.
- 현장·프로필 사진 업로드 API가 없습니다. 새 현장 사진은 서버에 보내지 않으며 응답의 `fake-photo://` 접두어는 제거합니다. 직원↔기사 역할 변경·유형 활성/비활성·알림 삭제는 서버 API가 없어 로컬 전용입니다.
- 유일 총관리자의 탈퇴 차단은 서버에서 아직 보장하지 않아 UI의 총관리자 규칙을 유지합니다. 참여 인원 API는 연락처를 주지 않습니다. 참여 링크는 회사 코드에서 조합하고 QR 이미지는 정적 에셋입니다.
- 타임테이블 드래그는 HTML5 드래그 앤 드롭이라 터치 기기에서는 동작하지 않습니다. 끄는 동안 모양은 브라우저 기본 반투명 이미지입니다.
- 작업중 상세(`785:4522`)는 실제 종료 예정 시각 전일 때만 보입니다. 시드의 정확한 이름·날짜·건수와 시안이 다를 수 있으며 전기 기사 필터는 2명입니다.
- 첨부한 현장 사진을 지우는 방법, 마이페이지 저장 피드백, 안 읽은 알림 0건일 때 '안 읽음' 목록 모양은 시안이 없습니다. 마이페이지에서 올린 사진은 사이드바에 반영되지 않습니다(사진 아바타 시안 없음).
- Windows처럼 스크롤바가 자리를 차지하는 환경에서는 세로로 넘치는 화면(알림창, 기사 작업이력, 진행 보드 등)의 본문 폭이 스크롤바만큼 줄어듭니다.
- 기획·디자인 확인이 필요한 항목: 직원·기사 전환(조직 ERD 결정 '배타·전환 없음'과 Figma 역할 변경 모달 충돌), 총관리자 지정·해제 버튼 위치, 유형 활성화 모달 3종의 의미, 작업유형 '색상' 열(머리글만 있고 색 선택 UI 없음), 새 유형 행 위치, 알림 종류(Notion 화면설계와 Figma 차이), 수락 완료 알림 상세 제목('작업 배정됨'), 회사 코드 발급 전 표시, 기간·상태 필터 선택지, 지어낸 안내 문구.
